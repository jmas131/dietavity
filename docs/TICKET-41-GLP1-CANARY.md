## Migration

File: `database/migrations/20260913_ticket_41_glp1_offer_context.sql`

```sql
-- Additive campaign context; no backfill and no privilege changes.
BEGIN;
ALTER TABLE public.onboarding_sessions
  ADD COLUMN offer_context text,
  ADD CONSTRAINT onboarding_sessions_offer_context_check
    CHECK (offer_context IS NULL OR offer_context = 'glp1_validation');
COMMIT;
```

The schema snapshot includes the same nullable column and constraint. Existing rows remain NULL. No grants, RLS, other constraints, or indexes change. This migration is applied once through the normal migration process.

## Detection and persistence

`lib/sales-engine-v3.js::detectOfferContext` uses NFC normalization, whitespace trimming/collapse, and case-insensitive comparison while preserving punctuation and accents. Only `¡Hola! Quiero saber más.` matches. The generic `¡Hola! Quiero más información.` remains distinct. Semantic fallback is intentionally omitted.

`Get Onboarding Session` now uses the existing PostgreSQL credential and node version, with a parameterized JSON payload. Before AI classification, an UPDATE CTE sets only `offer_context` on the matching existing `session_id` when it is NULL and the exact campaign was detected. Its RETURNING row takes precedence over the snapshot SELECT, so downstream nodes receive the newly persisted value in the same turn. No unrelated state or timestamps are reset. No row still follows the existing initializer branch; query errors propagate normally.

`Initialize Sales Lead v3` inserts the context on new sessions. Its existing primary-key conflict target (`session_id`) retains canonical context with COALESCE and preserves all unrelated fields. Both paths return every session column. Subsequent messages load the durable value without inspecting chat history. The final response continues through the existing canonical reservation, Twilio, provider evidence, and inbound completion path.

## Canonical knowledge and policy

`lib/dietavity-knowledge.js::GLP1_SALES_KNOWLEDGE` is appended to sales knowledge only when the loaded session has the canary context. It describes adults already using medication under medical supervision, the practical value proposition, the same existing product, self-prepared food, and medical limitations. It is not added to meal-generation or paid-assistant knowledge.

The policy returns the exact requested discovery question without price or Checkout, even if classification fails or incorrectly labels the icebreaker as purchase intent. Practical discovery goals use a contextual response without storing a health research category as the sales goal or inventing a purchase-confirmation question. Medication questions receive a deterministic prescriber referral; serious symptom language receives a medical-attention redirect. The final validator preserves the discovery response and adds a canary-only conservative guard for unsupported medication instructions, efficacy/nutrient/muscle claims, and internal campaign identifiers. These language checks supplement the prompt and are not an exhaustive medical classifier.
