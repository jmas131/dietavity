# Ticket 63 — Reviewed Knowledge & Bounded Practical Reasoning

This stage resolves exactly one Ticket 62-deferred `practical_guidance` obligation. It is not integrated into customer traffic, workflows, actions, policy, or canonical product facts.

Ticket 72 supersedes the original fixture-shaped corpus with `config/sales-engine-v2/reviewed-nutrition-knowledge.json`, a versioned reviewed authority. `config/sales-engine-v2/reviewed-knowledge.json` and its store remain compatibility fixtures for Ticket 63 regression coverage only; they are not a production authority source. The injected authority adapter returns one exact reviewed record or no match; active conflicts fail closed.

Routing is closed and structured: `food_storage` and `meal_preparation` map only to same-named topics; it has no behavioral mode fields. Every mapped `knowledge_question` in Ticket 63 v1 follows the deterministic direct-reviewed path, using `direct_reviewed` as the item allowed use. Raw customer language is never searched. Unmapped subjects and absent eligible knowledge become source-null `bounded_unknown` results with required customer uncertainty. Explicit `KNOWLEDGE_STORE_UNAVAILABLE` becomes a source-null `resolver_failure`; corrupt or ambiguous stores fail the call.

Knowledge questions resolve directly from reviewed content with `reviewed_knowledge` authority and exact retrieved references. The result artifact identity is the stable `practical-guidance-resolver` / `ticket-63-v1` pair; it contains no customer text. Transformation and organization use an injected synchronous reasoning function. Its input is only prompt version, obligation ID, task kind, optional structured subject, locale, and the owned typed bounded inputs. The model may return only `{units:[{unit_type,content,bounded_input_ids}]}` with the task-kind-matching type. The resolver, not the model, assigns generated authority and provenance, including caller-supplied `model_run_id`.

Every natural-language payload remains marked `semantic_safety_validation_required: true`. Structural grounding and bounded-input ownership do not certify the prose for customer delivery. A future semantic gate must do that. Future persistence or full-text/vector retrieval can implement the same injected store interface without changing these authority semantics.

## Ticket 63A — durable assessment-context binding

Every resolved `reviewed_knowledge` or `generated_guidance` terminal result additionally carries the closed, non-authoritative binding `{ version: 'ticket-63a-v1', digest: <lowercase SHA-256 hex> }`. `bounded_unknown` and `resolver_failure` results carry no binding because they have no assessable natural-language payload. The binding is a deterministic integrity commitment, not reviewed-knowledge provenance, a safety clearance, a policy decision, an authorization, or customer-visible content.

The digest commits to the exact normalized semantic material supplied to Ticket 64: obligation ID, task kind, optional subject, locale, authority, source provenance, semantic-gate requirement, ordered guidance units and their grounding IDs, plus either ordered owned bounded inputs (`id`, `input_type`, `value`, `origin`) or ordered reviewed items (`id`, `version`, `content`). The version tag and array ordering are explicit protocol inputs; Node SHA-256 hashes their fixed ordered JSON tuple. It deliberately excludes raw history, current-turn evidence, confidence, model prompts, resolver/runtime metadata, and arbitrary object serialization.

Ticket 64 recomputes this same binding from its supplied terminal result and assessment context before calling the assessor. A mismatch fails closed; Ticket 64B may later bind the resulting gate to this commitment. The binding does not retain or reproduce the source material, and no downstream stage may infer authority from it.
