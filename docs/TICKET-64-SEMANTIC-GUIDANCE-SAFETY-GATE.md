# Ticket 64 — Semantic Guidance Safety Gate

Ticket 64 adds a central `SemanticGuidanceGate` artifact and does not alter `ResolvedObligation`. It accepts only a context-valid, resolved Ticket 63 practical-guidance terminal result with `reviewed_knowledge` or `generated_guidance` authority and `semantic_safety_validation_required: true`. Ticket 63A requires the terminal result's `assessment_context_binding` to exactly match the bounded semantic input that Ticket 64 will assess; a mismatch fails closed before the assessor is called.

## Ticket 64B — terminal guidance binding

Every newly produced gate is `ticket-64b-v1` and carries `terminal_guidance_binding: { version: 'ticket-64b-v1', digest }`. Its fixed ordered SHA-256 projection binds the terminal obligation/status/authority, exact source provenance, reasoning flag, ordered guidance units and grounding IDs, ordered reviewed references when present, and the structured Ticket 63A assessment-context binding. It is integrity metadata: neither it nor a matching gate establishes product truth, reviewed authority, execution, delivery, action authorization, or safety clearance independent of `gate_status`.

`gateMatchesTerminalResult(gate, terminalResult)` is the downstream-only matching primitive. It needs only a validated terminal result and gate—never raw obligations, customer history, bounded-input values, reviewed-item contents, or store access. It rejects malformed, unbound legacy, foreign-obligation, or substituted terminal material. Ticket 65 uses this match before projecting cleared guidance; legacy `ticket-64-v1` gates therefore cannot provide launch clearance. JSON Schema validates the closed gate/binding shape; executable matching recomputes the cross-object digest.

The injected assessor receives only task/locale, guidance units, result authority and source, plus either owned bounded inputs or exact aligned reviewed items. It returns `{ findings: [{ code, unit_index, rationale }] }`; it cannot return severity, a gate status, policy, facts, rewrites, or actions. The deterministic mapping is blocking for product/provider, commercial, medication-management, diagnosis/prescription, unauthorized-action, and reviewed-knowledge-contradiction findings; all other closed codes require review. No finding clears, any blocking finding blocks, and review-only findings are indeterminate.

The separate artifact contains stable gate identity/version, status, findings with deterministic severities, and assessor-run provenance. The only normalized runtime condition is `SEMANTIC_ASSESSOR_UNAVAILABLE`, producing an `indeterminate` artifact with no findings. Malformed assessor output fails the call. The gate performs no retrieval, production model call, response composition, action authorization, workflow integration, or source mutation.
